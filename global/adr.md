# Architecture Decision Records

## Purpose

Record meaningful decisions so future humans and AI assistants understand context, trade-offs, and consequences.

## When to Write an ADR

- A decision changes architecture, public API behavior, storage design, or operational behavior.
- Multiple reasonable options existed.
- The decision creates a meaningful constraint for future work.
- The decision rejects an option that is likely to be proposed again.

## Recommended Structure

1. Title
2. Status
3. Context
4. Decision
5. Alternatives considered
6. Consequences
7. Review trigger

## Rules

- Keep ADRs factual and concise.
- Record why the decision was made, not only what was chosen.
- Link related implementation changes when possible.
- Update status instead of rewriting history.
