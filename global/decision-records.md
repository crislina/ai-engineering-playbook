# Decision Records

Create a project ADR when a decision changes architecture, public contracts, storage, security, or operations; has credible alternatives; or constrains future work.

Record:

1. Status
2. Context and forces
3. Decision
4. Alternatives rejected
5. Consequences
6. Review trigger

Keep the reasoning factual. Update status instead of rewriting history. ADRs belong to the affected project, not this reusable playbook.
